## 2. Arquitectura Funcional Preservada

Se mantuvieron íntegros los módulos y flujos operativos existentes solicitados:
- **Portada pública P013 (`src/components/PublicLanding.tsx`)** aislada de Firebase y sin fuga de datos internos, conectada por enrutamiento limpio (`/`, `/acceso`, `/panel`, y fallback hash `#/acceso`, `#/panel` para GitHub Pages).
- **Inicio de sesión privado (`src/components/LoginView.tsx` / `src/components/LoginModal.tsx`)** sin autorregistro público ni tarjetas pre-cargadas con credenciales.
- **Inspector 3D del Nodo (`src/components/Node3DInspectorView.tsx`)** con carga diferida (`lazy`) y control granular de visibilidad por rol y usuario (`SuperAdminControlView.tsx` + `Navbar.tsx`).
- **Motor dinámico de alertas (`src/services/alertEngine.ts`)** con histéresis anti-flapping, detección de `faultFields` (ADC desconectado) y compatibilidad completa con dispositivos ESP32/ESP-NOW en `/dispositivos/{deviceId}`.

## 4. Nota sobre Persistencia Histórica 24/7

Actualmente la grabación en `/historial_telemetria/{deviceId}/{timestamp}` se realiza desde el cliente web autenticado (`recordTelemetryHistoryPoint`) cuando un usuario mantiene el panel abierto (con throttling de 5s/30s y timestamp estrictamente creciente). Si no hay navegadores abiertos mientras el ESP32 transmite en terreno, esos intervalos no se registran en el histórico hasta habilitar escritura directa en el firmware ESP32 o mediante Cloud Function en RTDB. Este punto queda formalmente detallado en `MINESAFE_PENDIENTES_EXTERNOS.md`.
